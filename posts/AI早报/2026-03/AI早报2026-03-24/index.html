AI早报（3.24）：大公司开始算账：沃尔玛弃用OpenAI意味着什么

2026年3月24日· 信息日期2026-03-23· 发布日2026-03-24· 怀川· 共10688字 · 约22分钟 · 阅读量 --
栏目 AI早报 归档 2026-03

今日速览

昨天最值得普通上班族留意的新闻，可能跟你的工作没直接关系，但会影响你以后用什么 AI 工具——零售巨头沃尔玛被曝悄悄停用了 OpenAI，转向自研和开源方案。这个消息在技术圈炸开，不是因为沃尔玛多有影响力，而是因为它戳破了一层窗户纸：那些年吹得最响的"用最强 AI 就对了"逻辑，在真实商业世界里根本站不住脚。

沃尔玛不是唯一一个在 AI 采购上"清醒"的大公司。与此同时，OpenAI 宣布将在 ChatGPT 免费版和美国 Go 用户中强制插入广告。这意味着什么？你现在免费用的 ChatGPT，以后可能会时不时弹出一个"你可能想了解的"推荐。这不是猜测，是 OpenAI 亲口说的商业化计划。两件事放在一起看，逻辑很清楚：大公司在算账，发现 OpenAI 太贵而且不够灵活；OpenAI 在想办法从免费用户身上找补收入。夹在中间的用户，可能要为这场博弈付出代价。

对于已经习惯用 AI 编程的开发者来说，昨天有几件事值得关注。先说好消息：Claude Code 的生态插件爆发了——GitHub Trending 显示，单日有超过 4500 颗 star 流向了 Claude Code 的增强工具。其中 everything-claude-code 贡献了 3724 颗 star，这个工具给你的 Claude Code 加上技能、本能、记忆、安全等一堆增强模块，相当于给 Siri 装了一整套外挂；claude-hud 则贡献了 834 颗 star，它能实时显示你的上下文用了多少 token、当前跑了几个 Agent、任务进度到哪了。简单说，Claude Code 从一个"会写代码的 AI"正在变成一个"可以有记忆和监控的 AI 编程平台"。

但热闹背后藏着风险。Anthropic 向第三方 Claude 工具 OpenCode 发了律师函，禁止它继续使用 Claude Max 服务。理由听起来合理——API 使用政策需要合规，但社区的解读是另一回事：Claude 的"开放"是有边界的，你以为自己在用 Anthropic 的能力，实际上人家随时可以喊停。如果你重度依赖非官方的 Claude 工具，这条新闻值得你认真读一读——OpenCode 昨天同时还爆出了认证故障，Issue #18342 和 #18315 都在反映 Claude OAuth 认证集中出问题。对企业用户来说，这种"工具热闘、政策不稳"的组合是个明确的警告：备选方案现在就该准备了。

同一天，Rust 核心团队成员 Niko Matsakis 在 HN 上发了一篇 AI 辅助编程的系统评估，帖子拿到了 95 分和 41 条评论，是昨天 HN 上最热的讨论。这篇文章没有吹 AI 多么厉害，也没有说 AI 不行，而是老老实实讲了 Rust 团队用 AI 编程的真实体验：效率确实提升了，但"AI 生成代码必须人工审查"这条底线他们从来没放弃过。评论区没有撕起来，大家都在认真讨论代码所有权和长期维护责任的问题。这种工程化的务实态度，和最近科技圈流行的"AI 泡沫论"形成了鲜明对比。Rust 团队的意思很明确：AI 是效率工具，但不是你偷懒不写测试的理由。如果你正在公司推广 AI 编程工具，这篇文章是一份现成的风险告知模板——用它来对齐团队预期，比你拍胸脯说"装了 AI 效率翻倍"要靠谱得多。

字节跳动昨天在 GitHub 开源了一个叫 Deer-Flow 的项目，单日拿到了 1690 颗 star。这个工具定位是"SuperAgent harness"，翻译成人话就是：它帮你把沙箱、记忆、工具、技能、子智能体这些 Agent 需要的组件组合在一起，跑分钟到小时级别的长任务。它直接对标的是 OpenHands——后者现在有 69,557 颗 star，是这个赛道的头部玩家。同一天上榜的还有 TradingAgents（金融交易场景）和 pentagi（渗透测试场景），加上 Deer-Flow，说明多智能体协作框架正在从"通用"往"专业垂直"方向分化。大厂入局意味着什么？意味着这个方向被认可是真实的工程需求，而不是学术圈的自嗨。对正在调研 Agent 基础设施的团队来说，Deer-Flow 和 OpenHands 昨天都值得跑一遍 demo 比对一下。

最后说一个有点扫兴但不得不提的事：OpenClaw 昨天爆了一波回归 Bug。OpenClaw 是一个挺流行的 personal AI 助手框架，但它的 v2026.3.x 系列最近有点翻车。v2026.3.8 版本的网关心跳定时器直接停止工作了，76 条评论在讨论这个问题，最后定位到是 config 热重载逻辑的锅；v2026.3.12 版本的 Slack Socket Mode 连接成功但收不到消息；v2026.3.2 版本的 OpenRouter 认证头直接缺失，导致 401 报错。更要命的是，WhatsApp 通道显示"已连接"但实际发不出消息，Telegram 轮询客户端在网络故障后直接卡死。OpenClaw 昨天有 500 条 Issues 和 500 条 PRs 更新，听起来很活跃对吧？但 PR 合并率只有 28%，359 个 PR 在排队等合并。这意味着什么？Bug 越修越多，高优先级的安全问题（密钥加密、RBAC 权限控制）已经积压了 48 天没人理。对于已经在用 OpenClaw 的同学，建议今天打开你的版本号，对照已知回归 Bug 列表看看有没有中招。对于正在评估 personal AI 助手工具的团队，这个稳定性记录需要认真考虑进去——快速迭代不等于质量可靠。

综合来看，昨天 AI 圈发生的事有一个共同主线：潮水在退，大家开始算账了。大公司在算 AI 服务的成本和可控性，工具开发者在算功能迭代和稳定性的平衡，普通用户在不知不觉中被广告包围。Rust 团队的那句话放在这个大背景下格外应景：“人类审查不可妥协。“无论是代码审查，还是对 AI 工具的评估，保持清醒的判断力可能是今年最重要的一种能力。

如果你今天想做个什么：打开 GitHub 搜一下 everything-claude-code 和 claude-hud，看看有没有能直接解决你痛点的功能；如果你用 OpenClaw，对照已知 Bug 列表检查一下版本号；如果你在用付费 AI 服务，顺手查查有没有对应的开源替代方案。这三件事花不了半小时，但能帮你少踩几个坑。

这对你意味着什么

普通人

大公司开始自己搞AI了，免费工具以后可能越来越难用。 沃尔玛这样的零售巨头被曝悄悄停用了OpenAI，转向自己开发或者用免费的开源方案。这不是小打小闹——大公司做这个决定通常是算了好几遍账，发现每年交给AI服务商的钱实在太多了，而且用别人的东西改不了、控不住。你现在选AI工具也可以想想这个问题：花这么多钱值不值？

OpenAI要在免费版ChatGPT里塞广告了。 他们自己说的，不是我猜的。如果你一直用免费版，以后看聊天记录的时候可能会时不时冒出来一个推荐内容。这对普通用户来说不是什么大事，但至少说明一件事：免费的东西不会一直免费，早晚要找补回来。你要是觉得广告烦，可能得考虑掏钱了。

有没有免费又好用的替代？ 现在确实有，比如可以在自己电脑上跑的大模型，不用联网、不用注册、不会被收集数据。效果肯定比不上最强的付费服务，但日常问问题、写东西、改文章够用了。换句话说，别把所有希望都押在一家公司身上，多试试不同的选择。

如果你用AI帮工作，以后可能要多掏腰包。 大公司要算成本，AI服务商要找收入，两头挤压之下，付费服务涨价是大概率事件。趁现在还没涨，可以去了解一下你用的服务有没有开源替代，或者有没有更便宜的套餐。别等到账单来了才后悔。

AI工具和企业正在互相适应，别被忽悠了。 最近各种AI工具出问题的不在少数——要么悄悄多收钱，要么修bug修不过来，要么政策说变就变。听起来好像AI很厉害，但真金白银往外掏的时候，大家都在重新掂量。这对普通用户是好事，说明市场在回归理性，不会再有人吹牛说"装了这个AI效率翻三倍"——因为大公司自己都不信这套了。

开发者

今天去GitHub搜一下 everything-claude-code 和 claude-hud，这两个插件值得你花半小时看看。 everything-claude-code 单日拿了3700多颗star，总数快破10万了，它给Claude Code加上了记忆持久化、技能模块、安全增强这些功能，相当于给Siri装了一整套外挂；claude-hud 则给你实时显示上下文用了多少、当前跑了几个Agent、任务进度到哪了。如果你每天用Claude Code超过两小时，这两个工具装上就能解决真实痛点——不用自己写脚本，不用折腾配置。

Rust核心团队的系统评估文章值得通读一遍，然后在你的团队里传播一下。 他们没有吹AI多厉害，也没有说AI不行，而是老老实实讲了用了之后的真实感受：效率确实提升了，但"AI生成代码必须人工审查"这条底线他们从来没放弃过。这篇文章拿来跟团队对齐预期特别合适——用它告诉老板"装了AI不能少雇人"，比你拍胸脯说"效率翻倍"要靠谱得多。

检查一下你现在跑的OpenClaw版本号，对照已知回归Bug列表看看有没有中招。 v2026.3.8的网关心跳定时器直接停了、v2026.3.12的Slack收不到消息、v2026.3.2的OpenRouter直接401报错。更要命的是，项目今天有500条Issues和500条PRs更新，但PR合并率只有28%，359个PR在排队，高优先级的安全问题（密钥加密、RBAC权限）已经拖了48天没人理。如果你依赖OpenClaw的WhatsApp或Telegram通道，今天一定要检查一下发送功能正不正常。

如果你重度依赖OpenCode这类第三方Claude工具，开始准备备选方案吧。 Anthropic昨天给它发了律师函，禁止它继续用Claude Max服务。理由听起来是合规需要，但社区的解读是Claude的"开放"是有边界的——你以为你在用Anthropic的能力，人家随时可以喊停。加上OpenCode昨天同时爆出了认证故障（Issues #18342和#18315），短期稳定性存疑，企业用户不建议现在大规模部署。

Claude Code的Cowork目录限制争议已经积累了一百多条评论，顺手去看看进展。 这个Issue讨论的是Claude Code在处理多目录协作时的行为是否符合预期，评论破百说明不是小众问题。如果你的工作流涉及多个项目目录，值得关注这个Issue的走向——可能影响你后续的工作方式。

AGENTS.md标准正在获得Claude Code、Cursor、Codex社区共同推动，今天在项目根目录加一个。 这个文件相当于给AI编程助手的一份项目说明书，告诉它你项目的特殊配置和约定。如果你的项目还没加AGENTS.md，现在去根目录建一个，把项目的构建方式、依赖环境、常见陷阱写进去，以后换工具或者换人接手都会省很多事。

Codex的LSP支持拿到了200多个赞，如果你在用OpenAI的编程工具，关注一下这个需求的进展。 LSP是让编程工具"看懂"你代码结构的技术，有了它AI就能更准确地帮你补全和修改，而不是在错误的地方瞎猜。如果你用Codex或者Copilot，这个功能落地之后体验会明显提升。

Windows用户在选AI CLI工具时要额外测试一下，企业环境的域策略和杀毒软件可能会引发奇怪问题。 Claude Code、Codex、Copilot在Windows上都存在已知稳定性问题，多个工具在企业环境下的认证流程也有坑。如果你的团队主要跑Windows，选型的时候别只看功能列表，先在真实环境里跑几天再决定。

创业者/产品人

企业AI采购逻辑正在从"谁的模型最强"转向"谁的成本最合适、谁能让我自己改"。 沃尔玛弃用OpenAI不是个案，它代表了一种趋势：大公司在实际使用中发现，AI服务的成本和灵活性的账算不过来。如果你负责公司AI选型，今年要准备好回答"一年多少钱"和"能不能自己改"这两个问题——老板和财务会问的。

自研和开源的TCO可能比你想象的低，算一算吧。 沃尔玛这种体量的公司都转向自研和开源了，说明这条路不是小公司的无奈之选，而是真实可行的商业决策。如果你每年在AI API上花的钱够养一个工程师，可能就该认真评估一下自研方案了——一次性投入，长期受益，而且数据不用再往外送。

字节跳动入场SuperAgent赛道，这个方向被大厂认可是真实的工程需求了。 他们开源的Deer-Flow昨天拿了1690颗star，直接对标这个赛道的头部玩家OpenHands（现在有近7万颗star）。如果你在调研AI基础设施，这两个项目今天都值得跑一遍demo比对一下——大厂开源的好处是文档和社区通常比学术项目更完整，但也要留意背后的商业意图。

垂直场景的Agent框架开始实用化了：金融交易、渗透测试都有专门工具上榜。 TradingAgents和pentagi昨天在GitHub Trending上拿到1000多颗star，分别对应金融交易和渗透测试场景。这意味着多智能体协作已经不是"通用AI"的概念炒作，而是开始解决具体行业问题了。如果你的业务有类似的复杂决策场景，这个方向值得投入研发资源。

重度依赖第三方Claude工具的团队，Anthropic的律师函是明确的政策风险信号。 他们向OpenCode发律师函禁止使用Claude Max，说明第三方工具的"开放"是有边界的——你以为自己在用Anthropic的能力，实际上人家随时可以喊停。如果你的产品基于第三方Claude工具，今天开始准备Plan B方案，不要把鸡蛋放在一个篮子里。

AI CLI工具的认证稳定性正在成为采购决策因子，功能列表反而不是最重要了。 现在Claude Code、Gemini CLI、OpenCode是第一梯队（Issue量超过50个），但跨工具的共同瓶颈是认证可靠性——动不动就401报错、OAuth抽风，这才是影响生产环境使用的关键。如果你选型AI CLI工具，先问清楚认证流程的健壮性，跑几天真实场景再决定。
