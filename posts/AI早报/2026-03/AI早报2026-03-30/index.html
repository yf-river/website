AI早报（3.30）：你用的 Claude Code，可能正在给钓鱼网

2026年3月30日· 信息日期2026-03-29· 发布日2026-03-30· 怀川· 共16526字 · 约33分钟 · 阅读量 --
栏目 AI早报 归档 2026-03

今日速览

你今天打开 Google 搜索 Claude Code，结果第一条是个钓鱼网站。这不是段子，是昨天 Claude Code 用户社区真实发生的事情。更糟糕的是，同一天 Claude Code 还被曝出权限绕过漏洞，被社区标记为 SECURITY 级别。Cowork 功能在 Windows 二级驱动器下直接卡死，195 个人给相关 Issue 点了赞。截至发稿时 Anthropic 尚未发布正式修复公告，但维护团队正在处理 10+ 热点 Issues 和 10 个 Open PR。这个曾经被视为 AI 编程标杆的工具，正在经历一场信任危机。

这还没完。OpenClaw 昨天发布了 v2026.3.28-beta.1 更新，结果因为 pi-coding-agent 0.63.0 的破坏性升级，所有用户的嵌入式 Agent 认证全面失效，屏幕上全是「No API key for provider」错误。维护团队 24 小时内合并了 5 个紧急修复 PR，涵盖 Web-UI、Gateway、CLI、Commands、Agents 多个模块，还有一个大型合并 PR #56665 把跨模块改动一口气打包进去。OpenClaw 用户群的日常是：每次大版本更新都像拆盲盒，不知道哪个依赖项会突然叛变。这次的教训是：升级前先跑一遍 openclaw doctor，确认 pi-coding-agent 版本兼容性再动手。

在安全圈另一边，Anthropic 疑似泄露了代号「Claude Mythos」的新模型。Gizmodo 直接用「史无前例的网络安全风险」来形容，CNBC 跟进报道说网络安全股票应声下跌。但有意思的是，TechCrunch 同时指出 Anthropic 的付费用户数正急剧攀升。你看，市场对 AI 的态度就是这样分裂：一边担心 AI 越来越强大带来的威胁，一边又忍不住掏出钱包去买更强的能力。HN 社区多条相关帖子虽然分数分散，但共同构建了一套叙事框架：能力越强，威胁越大。这套叙事正在被市场定价——安全赛道可能会因此受益，但对企业来说，把安全评估前置到 AI 工具选型阶段，已经是不得不面对的事情。

说完让人焦虑的，来个好消息换换心情。开源项目 obra/superpowers 今天新增了 2292 stars，直接登上 GitHub Trending 榜首。这个项目的定位很有意思：自称「Agentic Skills Framework」，试图用 Shell 脚本定义 AI 原生开发的标准工程范式。社区里有人把它类比成 2013 年的 React——那一年 React 重新定义了前端组件化，现在 obra/superpowers 正在做同样的事情，只是对象换成了 Agent 开发。这意味着什么？AI Agent 的工程化正在从「手工作坊」走向「工业化」阶段。如果你关注工具链机会，这个项目的生态采纳度值得盯紧。

MCP 协议标准化也在加速。AI 工作流自动化平台 activepieces 已经集成了大约 400 个 MCP 服务器，成为 MCP 生态最大的聚合器之一。开发者 jackwener/opencli 提出了 AGENT.md 统一接口协议，想让不同 Agent 之间的发现、学习、执行链路有一套通用标准。更重量级的是，Google 官方 Workspace CLI（22,905 stars）内置了 AI Agent Skills，把 Drive、Gmail、Calendar 这些企业工具统一成 Agent 可调用的命令接口。Model Context Protocol 正在从 Anthropic 的私有设计演变成社区共识。对于开发者来说，多 Agent 协作的摩擦成本即将大幅下降——选工具的时候，优先考察它支不支持 MCP 协议，能帮你省下不少集成工作。

说几个社区里的有趣讨论。HN 昨天最热的帖子不是某个新模型发布，而是一个开发者 BoWang87 分享用 LLM 配合 Lean/Coq 这些形式化证明助手，攻克 Knuth 提出的「Claude Cycles」数学难题。这个帖子拿到了 131 分和 90 条评论，社区热烈讨论 proof assistant 与 LLM 结合的方法论。对于研究者来说，这意味着 AI 辅助数学证明已经进入可复现阶段；对于普通开发者来说，理解这套组合可能是下一代 AI 编程工具的基础能力——毕竟，让 AI 自己证明自己的代码是对的，比让它自己写测试用例更近一步。

另一个引发共鸣的帖子标题是「The risk of AI isn’t making us lazy, but making lazy look productive」，翻译过来就是「AI 的风险不是让我们变懒，而是让懒惰看起来像生产力」。59 分、55 条评论，社区共鸣强烈。大家讨论的核心问题是：AI 是否正在模糊「低效忙碌」与「真正产出」的界限？当你用 AI 五分钟生成一份报告，而同事手动做需要两小时，领导的评估标准该怎么调整？这 55 条评论构成了一个关于「AI 时代生产力幻觉」的群体反思，值得管理者和每个想让团队用好 AI 工具的人认真读一读。

开源社区昨天还冒出一个新词：slopware。Codeberg 上的项目 small-hack/open-slopware 提出了这个概念，指的是 AI 生成的低质量代码垃圾。涉及开源许可证修订、代码溯源等实操议题。虽然这个帖子只有 4 分、2 条评论，但反映的是开源社区对 AI 生成代码污染的真实焦虑。对于开源维护者来说，迟早要在许可证里明确是否接受 AI 贡献；对于使用开源组件的团队来说，关注依赖项的来源声明是否包含 AI 生成部分，可能很快会成为合规审查的一部分。

再来看其他 CLI 工具的动态。OpenAI Codex 昨天有 4 个 PR 在协同推进子代理运行时面板开发，同时 Token 燃烧问题引发了 315 条评论讨论，显示多代理架构正成为这个工具的核心迭代方向。社区同时关注 Codex 工具执行完全静默失败的问题——声称调用成功但实际上什么都没做。在 kimi-coding/k2p5 场景下尤为突出。Gemini CLI 则在推进 SDD（结构化驱动开发）工作流，同时发布 v0.36.0-preview.6 和 v0.35.3 两个版本补丁，战略清晰但执行还在追赶中。相比之下，GitHub Copilot CLI 昨天有 34 个 Issues 更新但 0 个 PRs，完全是官方主导的开发模式，社区贡献渠道受限——产品成熟，但创新也停滞了。

Kimi CLI 和 Qwen Code 作为国内开发者的替代选择，昨天分别活跃着 8 个和 12 个热点 Issues。Kimi CLI 在做 ACP 认证体系重构，Shell 执行器配置问题还没修好；Qwen Code 在处理 Windows 兼容性和代码审查增强，但子代理完备性还有明显短板。这两款工具在本土化和中文场景上做了优化，快速迭代追赶，但和国际工具相比，稳定性与功能深度仍有差距。非关键场景可以试用，核心项目建议还是评估国际工具。

OpenCode 昨天出现 Claude Max 严重故障，单条 Issue 引发了 393 条评论和 358 个点赞，成为社区热度最高的 AI CLI 事件。这个开源项目因为可扩展性和多 Provider 支持有吸引力，但稳定性和 OAuth 认证问题意味着生产环境部署需要充分测试和备用方案。与此同时，TinyClaw 作为 OpenClaw 生态中最轻量的项目，昨天 7 个 Issues 关闭、15 个 PRs 合并，呈现「零积压」状态进入阶段性代码冻结，是生态中唯一一个没有积压压力的项目——这代表了一种质量优先而非功能堆砌的开发节奏。

最后给普通上班族画个重点：Claude Mythos 泄露引发安全焦虑，Claude Code 遭遇钓鱼网站和权限漏洞双重危机，但 Anthropic 的付费用户数同时在急剧攀升——市场对 AI 的态度就是这么分裂，一边担心风险，一边忍不住掏钱。这个现象对你的直接影响是：检查一下你常用的 AI 工具（比如 Claude Code）是否有钓鱼网站冒充，遇到可疑链接直接去官网确认。这是最简单、最有效的自保方式。

对于开发者来说，今天最重要的三件事是：检查 Claude Code 是否使用了 dangerously-skip-permissions 选项，如果是就先关闭，因为权限绕过漏洞还没修；检查你团队的 AI 工具是否支持 MCP 协议，如果支持就把现有的工具连接器数量记录下来，作为后续选型的参考；打开 obra/superpowers 的 GitHub 页面读一读它的 README，理解 Agentic Skills Framework 的核心理念，这可能代表 Agent 开发的下一个方向。另外，如果你依赖 Discord 集成使用 OpenClaw，评估一下是否有 Telegram 或其他替代通道可以作为备份——OpenClaw 的每次大版本更新都可能让某个集成通道突然失灵。

对于考虑进入 AI 赛道的创业者或产品人来说，MCP 协议生态正在快速标准化，这是平台级别的机会——围绕 MCP 的工具链、安全认证、监控运维都可能催生新产品。而安全合规正在成为企业采购的硬门槛，把安全评估前置到选型阶段已经不是可选项。如果你们在服务企业客户，现在是把安全能力当作核心卖点来打的时候了。

这对你意味着什么

普通人

AI工具越来越强大了，但骗子也在用同样的技术。 昨天有用户发现，在 Google 搜索 Claude Code 时，第一条结果是个钓鱼网站——也就是说，当你以为自己在用这个工具时，可能已经把账号信息送给了骗子。这个问题不是工具本身的问题，但任何用过 Claude Code 的人都可能遇到。建议今早检查一下你收藏的链接，最好直接去官网而不是通过搜索结果进入。

你担心的AI安全问题，市场也在担心——但这不妨碍大家继续掏钱。 Anthropic 疑似泄露了一个代号叫 Claude Mythos 的新模型，科技媒体直接用了「史无前例的网络安全风险」这种标题，网络安全相关的股票应声下跌。但与此同时，Anthropic 的付费用户数正在急剧攀升。这说明什么？市场对 AI 的态度很分裂：一边担心风险，一边又忍不住去买更强的能力。对你来说，这意味着 AI 工具会越来越便宜还是越来越贵，可能取决于安全事件的发展。

有人开始专门给「AI写的垃圾代码」起了名字。 开源社区最近冒出一个词叫 slopware，翻译过来大概就是「AI生成的软件垃圾」。这个词听起来有点刻薄，但背后说的是一个实际问题：有人开始担心 AI 生成的代码正在污染开源项目，比如许可证里没说明这个代码是 AI 写的，或者代码质量低到没法维护。这跟你有什么关系？如果你用的某个免费工具是基于开源项目改的，这个项目里可能已经有 AI 贡献了——只是没人告诉你而已。

今天的热搜项目 obra/superpowers，可能在定义AI编程的下一个阶段。 这个开源项目昨天一天就增加了 2292 stars，直接登上了 GitHub 热榜第一名。它想做的事情是给 AI 编程工具定一个标准化的开发规范，让不同的 AI 助手能更好地配合工作。有人把它比作 2013 年的 React——那一年 React 重新定义了怎么做网页前端，现在这个项目可能在做类似的事，只是对象换成了 AI 编程。对你来说，这意味着 AI 编程工具可能正在从「各自为战」变成「流水线作业」，以后出来的工具可能比现在好用得多。

MCP协议正在让AI工具之间互相连通，Google都下场了。 MCP 的全称太技术化了，但你可以理解成「让不同 AI 工具能互相说话的标准」。现在有一个叫 activepieces 的平台已经接入了大约 400 个这种标准的服务器，Google 官方也把 Gmail、日历、网盘这些办公工具做成了 AI 可以直接调用的接口。对你来说，如果你的公司开始用 AI 工具处理工作流程，未来这些工具之间的切换可能会比你想象的顺畅——但前提是它们用的是同一种「语言」。

你常用的AI工具可能正在模糊「真正干活」和「看起来很忙」的界限。 社区里有个帖子这几天挺火的，标题翻译过来就是「AI的风险不是让我们变懒，而是让懒惰看起来像生产力」。比如你用 AI 五分钟生成一份报告，同事手动做需要两小时，那领导的评估标准该怎么调整？这 55 条评论构成了一个集体反思：当你用 AI 做事时，哪些是你真正创造的价值，哪些只是让低效看起来合理了？这个问题没有标准答案，但值得每个人想一想。

开发者

立即检查你的 Claude Code 是否用了权限跳过选项。 昨天 Claude Code 被社区标记了一个 SECURITY 级别的权限绕过漏洞，截至发稿时 Anthropic 尚未发布正式修复公告。如果你在自动化脚本里用了 –dangerously-skip-permissions 或者类似跳过权限检查的选项，现在应该先关闭它，或者把相关任务改到隔离环境里跑。钓鱼网站事件也提醒你检查一下团队内部的文档和书签，看看有没有链接到了假网站。

OpenClaw 用户现在不要急着升级，先跑一遍诊断。 v2026.3.28-beta.1 因为 pi-coding-agent 0.63.0 的破坏性升级，导致所有用户的嵌入式 Agent 认证全面失效，屏幕上全是「No API key for provider」错误。维护团队 24 小时内合并了 5 个紧急修复 PR，但你的环境可能还没更新。执行 openclaw doctor 检查当前认证状态，确认 pi-coding-agent 版本兼容性，然后再决定是否升级到最新版本。如果你在 CI/CD 流程里跑 OpenClaw，建议增加对这类认证回归的集成测试，防止下次升级突然阻断部署。

Windows 环境下的 AI CLI 工具有系统性问题，需要专门测试。 昨天整理发现，Claude Code 的 Cowork 功能在二级驱动器下卡死、Kimi CLI 的 Shell 执行器配置问题、Qwen Code 的命令执行失败、OpenAI Codex 的路径解析、以及 OpenClaw 的 exec 白名单，五款主流工具都存在 Windows 专属缺陷。这个不是某一个工具的 bug，而是整个生态对 Windows 的忽视。如果你或你的团队在 Windows 上用这些工具，应该专门测试一遍文件系统访问、路径处理、Shell 执行这些场景，把异常记录下来作为内部知识库。如果这类场景是高频使用，考虑备一个 WSL2 或 macOS 环境作为备份。

盘点一下你团队工具链的 MCP 协议支持情况。 MCP 生态正在快速标准化：activepieces 已经集成了 400 多个 MCP 服务器，Google Workspace CLI 把 Drive、Gmail、Calendar 统一成了 Agent 可调用的接口，AGENT.md 统一接口协议也在推进。选工具的时候，支不支持 MCP 协议会直接影响你后续的集成成本——如果一个工具已经接入了 400 个服务器，你就不用自己从头做连接器了。建议现在就把团队使用的 AI 工具是否支持 MCP、支持多少个连接器记录下来，作为后续选型的参考指标。

读一读 obra/superpowers 的 README，理解 Agent 开发的下一个方向。 这个项目昨天一天涨了 2292 stars，定位是 Agentic Skills Framework——简单说就是想给 AI 编程定一个标准化的开发规范。它用 Shell 脚本实现了一套轻量架构，把 AI Agent 的开发从「手工作坊」推向「工业化」。类比 2013 年的 React 重新定义前端组件化，这个项目可能在做类似的事情。打开 GitHub 页面读一读它的 README 和 example 目录，理解它的核心理念，这会帮你判断行业对 Agent 标准化的共识程度，以及是否值得提前跟进。

OpenClaw 新增了并行子 Agent 编排工具，值得评估。 PR #56607 合并了 sessions_await 工具，支持并行子 Agent 编排——这是构建复杂多 Agent 工作流的关键能力。同时 PR #56616 让 /v1/responses 端点返回推理内容，Agent 执行透明度提升。如果你正在用 OpenClaw 做多 Agent 场景，这个并行编排能力可能直接影响你的架构选择。如果你在意 Agent 的可解释性和调试体验，关注这个端点返回的推理内容格式。

长期运行 Agent 的用户需要设计上下文压缩时的信息保留策略。 有用户反馈连续运行 11 天后，每 30 分钟一次的上下文压缩导致信息永久丢失，Memory v2 架构成为社区最期待的功能方向之一。如果你有类似的长期运行场景，建议提前设计信息保留策略：比如定期把关键对话和中间结果导出到外部存储，而不是完全依赖 Agent 的上下文窗口。这个问题目前没有完美解决方案，但可以缓解。

关注 OpenClaw 生态里的认证回归问题，如果你用 OpenRouter 或 Anthropic。 OpenRouter 用户遇到了 401 认证头缺失的问题，目前在 v2026.3.2 版本无法正常使用，相关修复还未合并。Anthropic 的 setup-token 认证在隔离环境中也有可复现的 401 失效。如果你是这两个 Provider 的用户，在升级前先确认认证流程是否正常，或者准备好回退方案。

检查你项目的开源许可证是否对 AI 贡献有明确声明。 slopware 概念的提出意味着开源社区开始认真对待 AI 生成代码的污染问题。建议检查你依赖的组件是否在许可证里声明了是否接受 AI 贡献，这可能影响后续的法律合规审查。如果你维护开源项目，考虑在 README 或 LICENSE 里明确立场。

创业者/产品人

MCP协议生态正在形成平台级别的机会，围绕它可以做的产品比你想象的多。 Google 官方 Workspace CLI、activepieces 的 400+ 服务器集成、AGENT.md 统一接口协议，这些信号指向同一个趋势：Model Context Protocol 正在从 Anthropic 的私有设计演变成社区共识。对于创业者来说，这意味着协议层正在标准化——你可以考虑围绕 MCP 做工具链、安全认证、监控运维这些周边产品，就像当年围绕 USB 协议做扩展坞和转接线一样。选赛道的时候，协议层的标准化往往意味着更大的整合空间。

向量数据库可能正在经历「柯达时刻」，检索技术栈面临重构。 开源项目 VectifyAI/PageIndex 提出的无向量推理型 RAG，加上 LEANN 实现 97% 存储压缩，这两个信号指向同一个方向：当模型可以直接消化长文本时，昂贵的向量索引需求可能下降。如果你的产品建立在向量数据库之上，需要评估这个技术趋势对你的业务冲击有多大。如果你的产品依赖 RAG 架构，文档解析精度可能是下一个差异化点——datalab-to/chandra 今天涨了 687 stars，专注复杂表格和手写体 OCR，填补了 RAG 质量的一个缺口。

安全合规正在从「加分项」变成「入场券」，如果你们服务企业客户，这是核心卖点。 Claude Mythos 泄露引发安全焦虑，网络安全股票应声下跌，但 Anthropic 的付费用户数同时在急剧攀升。这个分裂现象说明什么？企业对 AI 的采购正在把安全评估前置——不是可选项，而是必须项。对于 AI 工具产品的团队，这意味着你在 pitch 的时候，安全能力可能已经跟功能能力一样重要了。如果你的产品服务企业客户，现在是把安全合规当作核心卖点来打的时候了。

obra/superpowers 的生态采纳度值得盯紧，它可能代表 Agent 开发的工程化拐点。 这个项目昨天一天涨了 2292 stars，定位是定义 AI 原生开发的标准工程范式，社区反响强烈。如果你是做 AI 工具链产品的，这个项目的生态采纳度是判断行业共识程度的一个指标——当足够多的开发者开始用同一套规范开发 Agent，工具链的机会就会涌现。如果这个趋势成立，围绕 Agent 技能的标准化可能催生新的工具链需求，比如技能市场、技能测试、技能监控。

Google Workspace 与 AI Agent 的集成正在加速，企业市场的入口在变化。 Google 官方 Workspace CLI 把 Gmail、日历、网盘统一成了 Agent 可调用的接口，这意味着企业工作流的 AI 自动化入口正在从「人工操作工具」变成「Agent 直接调用」。对于做企业级 AI 产品的团队，这意味着你可能需要重新思考产品的接入方式——是继续做人工操作的辅助工具，还是直接做成 Agent 可以调用的接口。这个选择会影响你的产品定位和目标客户。

开源社区对 slopware 的焦虑会影响你们的技术选型和法务审查。 slopware 概念的提出意味着开源社区开始认真对待 AI 生成代码的污染问题——许可证要不要声明、代码要不要溯源、依赖项要不要审查。对于使用开源组件的团队，这可能影响你们的合规审查流程。对于做 AI 产品的团队，如果你们也依赖开源组件，可能需要提前准备代码来源声明，避免在合规需求来临时被动。
