AI早报（4.20）：一份RFC让OpenClaw社区吵翻了

2026年4月20日· 信息日期2026-04-19· 发布日2026-04-20· 怀川· 共11132字 · 约23分钟 · 阅读量 --
栏目 AI早报 归档 2026-04

今日速览

昨天 GitHub Trending 最大的黑马是一个叫 EvoMap/evolver 的项目——它一天之内猛涨 1,131 颗 stars，直接登顶榜首。这个项目做了什么？它把生物界的基因组进化协议（GEP）搬进了 AI Agent 的架构设计里。换句话说，以前开发者需要手动编排 Agent 的行为逻辑，现在 Agent 可以像生物进化一样，自己通过基因组突变和自然选择来优化。这不是某个实验性小项目，而是一个明确的技术宣言：开源社区正从"手工设计 Agent 行为"转向"让 Agent 自我演化"。如果你是 AI 开发者，这件事值得你现在就去 GitHub 把这个项目的 README 读一遍。

但同样是"让系统更可信"这件事，昨天在 OpenClaw 社区引发了截然不同的讨论。MolTrust 提出的 Agent 原生身份与信任验证 RFC（#49971）在一天内积累了 96 条评论，成为 OpenClaw 史上讨论最热烈的设计提案。这个 RFC 基于 ERC-8004、W3C DID、W3C VC 这些标准，试图给每个 Agent 分配一个去中心化身份，解决"谁在执行这个任务"的溯源问题。社区吵得这么凶，是因为这份 RFC 直接挑战了现有的信任模型——从"代码即信任"变成"可验证身份加行为声誉"双层体系。这不只是一个技术选型问题，而是关系到企业能不能合规使用这些 Agent 的准入门槛。更现实的是，同一天社区还曝光了 ClawHub 插件市场存在 341 个恶意 Skill，严重漏洞率高达 13.4%——你正在用的某个工具插件，可能就是其中之一。

和这个信任危机形成对比的是 Thunderbird 昨天推出的 thunderbolt 项目。它今天的 stars 增速虽然不如 evolver 夸张，但同样值得关注。Thunderbird 作为老牌邮件客户端，这次没有选择接入某个大模型的 API 然后交给用户付费，而是打出了"选择模型、拥有数据、消除锁定"的旗号——用户可以自己选择用哪个 AI 模型，数据完全留在本地，不被任何 vendor 锁定。这个方向和 Ollama、OpenWebUI 等本地部署工具的热度形成了共振，反映出一个正在壮大的趋势：开发者对闭源 AI 的围墙花园越来越不耐烦，普通用户对数据主权的意识也在觉醒。

如果你觉得上面这些离你还有点远，那 BasedHardware/omi 这个项目可能更能让你有体感。它昨天新增了 609 颗 stars，是当天第二热门的项目。omi 做了一个集屏幕视觉、语音听觉和主动建议于一体的多模态 AI 助手——简单说，它不是等着你下指令，而是随时看着你的屏幕、听着你的声音，然后主动告诉你该做什么。这代表了一种全新的产品形态：环境感知型 Agent 常时在线，不只是帮你执行任务，而是在你需要之前就出现。这种形态和现在的 ChatGPT、Claude Code 等工具完全不同，后者是你主动打开，它响应；omi 式的 Agent 则是你在哪它就在哪。

omi 代表的是产品方向上的探索，而 OpenAI 昨天继续保持高增长的 openai-agents-python 则代表了另一个维度的竞争——官方入场。这个框架单日新增 470 颗 stars，是 OpenAI 官方的轻量多 Agent 工作流解决方案。它的出现意味着 AI Agent 开发正式进入"官方支持"阶段：LangChain、AutoGPT 等社区框架在前，OpenAI 的官方栈在后，加上 Claude Code 生态的快速扩张，2026 年的 Agent 开发平台正在形成巨头割据的局面。如果你现在正在选型做 Agent 应用，需要认真考虑的一个问题是：选哪个生态，就意味着被哪个生态锁定。

昨天还有一个技术层面的进展值得关注：DeepSeek 开源了 DeepGEMM 项目，实现了 FP8 细粒度缩放的高效矩阵运算内核。这个项目的核心价值在于，它把 FP8 推理优化做成了一套可参考的技术方案，而且是国产项目做出来的——不是跟随，而是在特定领域定义标准。配合前面提到的 OpenClaw SQLite 持久化作业队列 PR（#68718）进入评审，你会发现"可信执行"正在成为 2026 年第二季度最明确的技术主线：任务不能丢、Agent 不能失控、系统不能因为崩溃而失联。

说了这么多，如果你今天在地铁上只有三分钟记住一件事：昨天 AI 工具圈最核心的变化是"信任机制正在重建"。无论是 OpenClaw 的身份 RFC、ClawHub 暴露的恶意插件、Thunderbird 的数据主权宣言，还是 OpenAI 的官方 Agent 框架，都在指向同一个问题——当 Agent 开始替人执行真实任务的时候，谁来保证它做的事是对的、它的身份是可验证的、它的数据是安全的。这个问题不是某个项目的内部事务，而是会影响你今天选择用哪个工具、怎么配置你的工作流的底层逻辑。

所以你今天可以做的事：如果你用 OpenClaw，打开配置文件检查一下权限设置是否已经执行了 chmod 0o600 加固；如果你在选型 Agent 开发框架，别只看功能列表，先看它的信任和身份验证机制是否完整；如果你只是想找一个更安全的邮件 AI 方案，可以去 GitHub 看看 Thunderbird thunderbolt 的具体实现逻辑，判断它是不是真的能满足你的数据自主需求。这三件事，任何一件做完，都比在地铁上刷三条新闻有用。
