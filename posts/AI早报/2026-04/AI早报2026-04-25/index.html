AI早报（4.25）：Claude Code 被黑、Anthropic 道歉、OpenAI 藏分

2026年4月25日· 信息日期2026-04-24· 发布日2026-04-25· 怀川· 共13560字 · 约28分钟 · 阅读量 --
栏目 AI早报 归档 2026-04

今日速览

昨天科技圈最讽刺的一幕发生在 Hacker News 上：搜索引擎排名第一的 Claude Code 下载链接指向的是一个恶意网站，大量不明真相的开发者在真官网之外中招。这个安全事件的水花还没完全散去，Anthropic 官方又罕见地发出一份 postmortem（事后分析报告），承认 Claude Code 确实存在质量问题，并把原因归咎于推理强度降级等三项变更。帖子发出后立刻冲上 HN 热榜，收获 527 分和 401 条评论——评论区俨然成了一场“众包质量报告”，工程师们纷纷晒出自己遇到的具体故障。这波操作在 HN 上创下当日互动量纪录，也把 Claude Code 这款工具推到了风口浪尖：它已经是 AI 编程领域的事实标准，但昨天发生的事说明，这个标准比很多人以为的更脆弱。

Anthropic 昨天遇到的麻烦还不止这一件。有安全研究者发现，Claude 桌面应用在安装时会悄悄部署一个原生消息传递桥接组件——本质上这是一个预授权的浏览器扩展，但用户在整个安装流程中从来没有被明确告知。更微妙的是，Anthropic 前脚刚宣布要求新用户上传身份证完成 KYC 验证，现在又爆出静默安装扩展，两件事叠在一起，让社区里一个观点迅速传播开来：Anthropic 正在变成它曾经公开反对的那种公司。这对 AI 公司的透明度是个严肃的拷问，尤其当 Anthropic 的核心用户群恰恰是最在意隐私的那批开发者时，这种信任裂痕的影响会比表面上看起来大得多。

GPT-5.5 昨天正式发布了，OpenAI 在基准测试里拿到了 1009 分，空降 HN 第一名。但诡异的是这家公司没有公布 ARC-AGI-3 的评测分数。紧接着一个独立帖子专门追问这件事，同样获得了社区关注。更能说明问题的是，OpenAI 同步发布了一份 59 页的安全文档 System Card，结果只拿到了 4 分和 0 条评论。社区最热的话题根本不在模型有多强，而在 OpenAI 为什么不把完整的评测结果亮出来。这种“选择性披露”的发布策略正在动摇开发者对基准测试的信任——当头部公司都开始挑选对自己有利的数据来展示，外界还能相信这些数字吗？昨天的 HN 讨论里，这个问题的热度远超 GPT-5.5 本身的性能。

有意思的是，就在 Claude Code 被安全问题缠身的同时，一个叫 free-claude-code 的开源项目横空出世。这个工具来自开发者 Alishahryar1，支持终端、VSCode 和 Discord 三个客户端，定位就是 Claude Code 的免费替代。4 月 23 日这一天，它在 GitHub 上狂揽 1962 个 Stars，增速全网第一。Claude Code 已经成为事实标准但付费门槛让很多个人开发者和小型团队吃不消，free-claude-code 的爆发式增长说明市场对低成本替代方案有极其强烈的需求。这个项目后续能走多远，能不能真正填补 Claude Code 留下的空白，会是接下来几周值得关注的事。

向量数据库领域的暗流涌动也值得插一句。VectifyAI 发布了一个叫 PageIndex 的项目，走的是“无向量、基于推理”的技术路线，不依赖传统的 Embedding 来做文档索引。与此同时香港大学团队 HKUDS 发布了 RAG-Anything 这个一体化框架，目标是把 RAG 从一个检索管道升级成知识操作系统。两条路线同时出现，指向同一个判断：传统依赖向量检索的 RAG 方案正在面临瓶颈——Embedding 的精度限制和边缘部署的存储开销是两个绕不过去的问题。如果推理驱动的方案能在准确率上追上现有水平，整个向量数据库市场的格局都会被重塑。

OpenClaw 生态昨天也上了热搜，但不是因为什么好消息。v2026.4.21 版本存在严重的 npm 依赖缺失问题，用户执行完 npm install -g openclaw@latest 之后程序直接崩溃。问题出在 Feishu/Lark 和 Nostr 这两个扩展的依赖没有正确打包进安装包，24 小时内冒出来 5 个相关 Issue。官方随后发布了 v2026.4.22 版本修复了这个问题，并且补上了 xAI 的多模态能力——图像生成、语音合成、语音识别和实时转录全都支持了。但 v2026.4.21 这个 P0 级别的事故对新用户体验的伤害是实打实的，项目虽然维持着日均 500 条 Issues 和 500 条 PR 的高活跃度，稳定性债务却在累积。生态横向对比来看，OpenClaw 的活跃度确实领先，但版本发布节奏过快导致的回归风险正在成为隐患。

社区里另一个值得注意的动向是关于 AI 代理身份验证的讨论。OpenClaw 社区正在热议一份 RFC 提案（Issue #49971），这个叫 MolTrust 的框架试图用 ERC-8004 和 W3C DID/VC 标准来解决 AI 代理之间的信任建立问题。帖子获得了 102 条评论，是社区里讨论最活跃的议题。102 条评论背后反映的是：当多代理协作开始成为现实，谁来保证代理 A 不会冒充代理 B？这不是纸上谈兵，而是 AI 代理网络化必须解决的基础设施问题。这个 RFC 的最终走向，会直接影响 OpenClaw 生态里多代理应用的演进方向。

说回普通人最该关心的——昨天的变化意味着什么。Claude Code 作为事实标准正在经历质量波动期，加上安全事件的叠加影响，用它来跑重要任务之前最好做一次完整回归测试。Anthropic 的隐私政策收紧和 KYC 政策同步推进，如果你在用 Claude 的桌面客户端，可能需要重新评估一下自己的隐私边界。与此同时，GPT-5.5 的评测透明度争议给所有人提了个醒：不要只看公司公布的数字，自己搭一套独立验证环境越来越有必要。工具在进化，但风险也在以同样的速度演化，先把回滚方案和回归清单过一遍，比盲目追新功能要安全得多。

  • 供应商"选择性披露"策略正在动摇基准测试公信力：GPT-5.5 的评测透明度和 Claude Code 的 postmortem 同步出现，指向一个共同信号——头部 AI 公司的产品发布正在从"技术领先叙事"向"风险管理叙事"过渡。产品定位时需将"供应商透明度"纳入评估维度，已建立的信任裂痕可能在用户决策链中被放大。
